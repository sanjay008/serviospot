ServioSpot Mollie — completed backend contract
=============================================

The backend below is what the app calls. The app reads only "data".
It never stores a Mollie key and never sends a price.

Base URL: POST https://app.erpportaal.nl/api/serviospot/{endpoint}
Auth: vendor token in the JSON body, same as the other ServioSpot calls.

{
  "status_code": 200,
  "status": true,
  "message": "...",
  "data": { }
}

1. Decide if Mollie checkout should open
-----------------------------------------
POST /api/serviospot/getPlans
Body: { "company_login": "catering" } or the vendor token.

data.payment
  "mollie" or "live"  -> open Mollie checkout
  missing, "preview", or anything else -> do not open Mollie

data.plans[]
  code, name, price_cents as a number (1995 means €19.95)

getSubscription may also return data.payment. The app checks getPlans first.

2. Free plan
------------
POST /api/serviospot/saveSubscription
{ "token": "<vendor_token>", "plan": "free" }

Free does not open Mollie.

3. Gold / Platinum
------------------
POST /api/serviospot/createMolliePayment
{
  "token": "<vendor_token>",
  "plan": "gold",
  "redirect_url": "serviospot://payment/mollie"
}

plan is only "gold" or "platinum". The app does not send an amount.

data:
{
  "payment_id": "tr_xxx",
  "checkout_url": "https://www.mollie.com/checkout/..."
}

Both must be non-empty strings. If either is missing, the app shows:
The server did not return a Mollie checkout link.

The app opens checkout_url. Mollie returns to serviospot://payment/mollie.
The app then calls:

POST /api/serviospot/getMolliePayment
{ "token": "<vendor_token>", "payment_id": "tr_xxx" }

data:
{
  "payment_id": "tr_xxx",
  "status": "paid",
  "plan": "gold"
}

data.status:
  paid / authorized                         success, plan is active
  open / pending                            still waiting
  canceled / cancelled / expired / failed   error, plan must not change

The app does not activate a plan from the deep link alone.

4. Invoices
-----------
POST /api/serviospot/getInvoices
{ "token": "<vendor_token>" }

data.invoices[]:
  id, number, plan, amount_cents, status, date

Rows appear after a successful Mollie payment.

5. Current subscription
-----------------------
POST /api/serviospot/getSubscription
{ "token": "<vendor_token>" }

Current plan is data.plan or data.code: free, gold, or platinum.
data.payment may be "mollie", "live", or "preview".

6. App sequence
---------------
Vendor token is already saved.
getPlans: Mollie UI only when data.payment is mollie or live.
Free: saveSubscription with "free".
Gold/Platinum while Mollie is on: createMolliePayment, open checkout_url,
then getMolliePayment. Success only for paid or authorized.
Then refresh getSubscription and getInvoices.

8. Do not
---------
Do not put the Mollie API key in the app.
Do not send a price from the phone.
Do not mark a plan paid from the redirect alone.
Do not call saveSubscription for gold or platinum while Mollie is on.
